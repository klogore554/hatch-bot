# Хаб-бот на Rust

Эта ветка — та же логика, что и в `main`, но на Rust. Запускается быстрее, ест меньше памяти, отвечает без пауз Python'а. Хендлеры, кнопки, рефералка, челлендж, Lava и документы — всё на месте.

Основная ветка на Python осталась в `main`. Разница только в языке и в том, что данные хранятся в одном JSON-файле вместо SQLite.

## Зачем ветка

- холодный старт заметно быстрее;
- один статический бинарник, меньше зависимостей на хосте;
- нет GIL и интерпретатора — на слабом железе отклик заметно ровнее;
- при большом числе пользователей расход памяти ниже.

На практике задержка ответа в основном зависит от сети до Telegram, но на дешёвом хостинге Rust всё равно приятнее.

## Что умеет

То же, что и Python-версия:

- `/start` с метками `?start=vid1` и `?start=ref123`;
- привычки, серии, `/remind 09:00` (МСК);
- групповой `/challenge` и `/top`;
- кнопки «📄 Документы»: оферта, возврат, политика данных;
- `/subscribe` → Lava recurrent → ссылка на оплату;
- проверка оплаты раз в минуту, автопродление Pro;
- предупреждение за 3 дня до конца подписки;
- `/health` для проверки деплоя.

Всё основное — кнопками, команды работают тоже.

## Запуск локально

Нужен Rust 1.75+ и токен от `@BotFather`.

```powershell
git clone <твой-форк>.git
cd habit-bot
git checkout rust
cargo run
```

Переменные задаются в окружении, `.env` не используется:

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | токен из `@BotFather` |
| `DB_PATH` | путь к JSON-базе, по умолчанию `habit.json` |
| `LAVA_SHOP_ID` | UUID магазина Lava |
| `LAVA_SECRET_KEY` | секретный ключ проекта |
| `LAVA_PRODUCT_ID` | UUID рекуррентного продукта |
| `LEGAL_NAME`, `LEGAL_INN` | данные продавца в оферте |
| `SUPPORT_EMAIL`, `SUPPORT_TG` | контакты поддержки |
| `PORT` | порт health-сервера, по умолчанию 8000 |
| `HEALTH_SERVER` | `1` — включить health-сервер |

```powershell
$env:BOT_TOKEN = "токен_от_botfather"
cargo run
```

Сборка релиза:

```powershell
cargo build --release
.\target\release\habit-bot-rs.exe
```

Проверка: `cargo test` — тесты логики привычек, рефералки и челленджа.

## Деплой

Railway сам определяет Rust по `Cargo.toml`. Start Command можно поставить:

```text
cargo run --release
```

Добавь Volume на `/data` и задай `DB_PATH=/data/habit.json`, иначе база потеряется при redeploy.

`GET /health` должен вернуть `{"ok":true}`.

## Структура

- `src/main.rs` — запуск, polling, планировщик, health-сервер;
- `src/handlers.rs` — команды и кнопки;
- `src/store.rs` — данные и тесты;
- `src/lava.rs` — платёжный клиент с HMAC-подписью;
- `src/legal.rs` — документы;
- `src/telegram.rs` — обёртка над Bot API;
- `CONTENT.md` — ролики и deep-link, общий для обеих веток.

## Что учесть при форке

1. Поменяй `PRESETS` в `src/handlers.rs` под свои привычки.
2. В `src/legal.rs` поправь тексты документов. Реальные реквизиты не пиши в файл — они приходят из переменных окружения.
3. В Lava создай свой рекуррентный продукт и задай три переменные `LAVA_*`.
4. Цена 299 ₽ зашита в текстах — поменяй её и в Lava, и здесь, и в `CONTENT.md`.
5. Метки `vid1…vid7` описаны в `CONTENT.md`.

Вывод денег делается в личном кабинете платёжного сервиса. Отдельного скрипта нет.

## Ограничения

- JSON-файл подходит для небольшого проекта. На тысячи пользователей лучше Postgres.
- Время везде московское. Другая зона — правка `msk()` в `src/store.rs`.
- Статусы оплаты Lava стоит проверить маленьким реальным платежом до рекламы.
- Если после цикла роликов нет продаж — чини оффер и трафик, а не код.
