# Хаб-бот

Телеграм-бот для привычек. Ставишь галочку каждый день, видишь серию, соревнуешься с другими в группе. Есть бесплатная версия и подписка Pro.

Если хочешь сделать свой бот — форкай репозиторий, меняй токен, название и тексты. Всё остальное уже работает.

## Зачем так сделано

Одиночная напоминалка быстро надоедает и не приводит новых людей. Поэтому внутри зашиты две вещи, которые работают без тебя:

- **Рефералка.** Кидаешь ссылку — двое друзей запустили бота, у всех троих +3 дня Pro.
- **Групповой челлендж.** В чате запускается `/challenge` на 7 дней, бот показывает рейтинг. Увидев отстающих, люди сами зовут других.

Плюс обычная польза: привычки, серии, напоминания, оплата подписки без сайта.

## Что умеет

- `/start` с меткой: `?start=vid1`, `?start=ref123` — видно, откуда пришёл человек и кто пригласил;
- привычки из списка и свои, в бесплатной версии одна, в Pro без лимита;
- кнопки «✅ Отметить» и «📊 Стрик», напоминание `/remind 09:00` по Москве;
- групповой `/challenge` и рейтинг `/top`;
- кнопка «📄 Документы»: оферта, возврат, политика данных;
- `/subscribe` → email для чека → ссылка на оплату Lava;
- раз в минуту бот проверяет оплату и сам продлевает Pro на 30 дней;
- за 3 дня до конца Pro приходит предупреждение.

Всё основное — кнопками. Команды тоже работают, но пользователю их искать не надо.

## Быстрый старт

Нужен Python 3.10+ и токен бота от `@BotFather`.

```powershell
git clone <твой-форк>.git
cd habit-bot
python -m pip install -r requirements.txt
$env:BOT_TOKEN = "токен_от_botfather"
python bot.py
```

Без ключей Lava бот запустится. `/subscribe` будет ругаться — это нормально, пока не настроена оплата.

Проверка живости: `http://localhost:8000/health` должен вернуть `{"ok":true}`.

## Переменные окружения

Никакого `.env` в репозитории нет. Всё задаётся на хосте.

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | токен из `@BotFather` |
| `LAVA_SHOP_ID` | UUID магазина в Lava |
| `LAVA_SECRET_KEY` | секретный ключ проекта |
| `LAVA_PRODUCT_ID` | UUID рекуррентного продукта |
| `DB_PATH` | где лежит база, например `/data/habit.db` |
| `PORT` | хостинг задаёт сам |
| `HEALTH_SERVER` | `1` — поднять `/health` |
| `LEGAL_NAME`, `LEGAL_INN` | данные продавца в оферте |
| `SUPPORT_EMAIL`, `SUPPORT_TG` | контакты поддержки в документах |

Если `LEGAL_*` и `SUPPORT_*` не задать, документы всё равно откроются — просто без реквизитов. Для реальной модерации их надо заполнить.

## Деплой на Railway

1. New Project → Deploy from GitHub repo.
2. Settings → Variables: добавь переменные из таблицы.
3. Settings → Volumes: смонтируй Volume на `/data`.
4. Start Command: `python bot.py`.
5. Проверь `GET /health`.

Volume нужен, чтобы база не исчезала при redeploy. Без него все привычки и серии обнулятся.

Любой хостинг с постоянным адресом подойдёт — Lava при модерации смотрит, что проект не на бесплатном временном домене.

## Оплата

Сейчас подключена Lava. Рекуррентный продукт создаётся в личном кабинете, цена и период задаются там же.

Webhook не используется: бот сам опрашивает `/business/recurrent/subscription/status` раз в минуту. Если статус «оплачено», Pro продлевается. Точные значения статусов лучше сверить с документацией Lava — в `payments/lava.py` есть функция `looks_paid()`, её легко подправить под другой провайдер.

Если захочешь другой платёжный сервис — меняй только папку `payments/`. Логика бота от этого не зависит.

Вывод денег делается в личном кабинете платёжного сервиса. Отдельного скрипта для этого нет и не нужно. Если позже понадобится вывод через API, у Lava есть методы `/business/payoff/*`, в том числе `trc20_payoff`; документация на сайте разработчика.

## Что видно покупателю

На странице оплаты — название магазина, продукт и цена. В чеке — данные продавца, которые требуют законы. В выписке покупателя — выплата от платёжного сервиса, а не твои реквизиты.

Документы, ИНН, адрес и телефон остаются в личном кабинете платёжного сервиса. В репозитории их нет.

Для поддержки можно использовать отдельный Telegram-аккаунт и отдельную почту. Главное — не теряй к ним доступ: почта с двухфакторной защитой и долгоживущий номер надёжнее одноразовых. Юридические данные при этом должны быть настоящими.

## Как форкнуть под себя

1. Удали старые метки `vid1…vid7` из `CONTENT.md` или замени своими.
2. В `bot.py` поменяй `PRESETS` — набор привычек под свою аудиторию.
3. В `legal.py` поправь тексты оферты, возврата и политики. Реквизиты не вписывай в файл — они приходят из переменных.
4. В `CONTENT.md` перепиши ролики под свой продукт. Там есть готовый каркас.
5. В Lava создай свой рекуррентный продукт и положи его ID в переменные.
6. Если нужна другая цена — меняй её и в Lava, и в текстах бота, и в контенте.

Структура небольшая:

- `bot.py` — хендлеры и кнопки;
- `db.py` — SQLite, всё хранится в одной базе;
- `legal.py` — тексты документов;
- `payments/lava.py` — платёжный клиент, единственное место, которое меняется при смене провайдера;
- `CONTENT.md` — план роликов и deep-link;
- `payoff` в репозитории нет — вывод через личный кабинет.

## Ограничения

- Одна привычка в бесплатной версии — это лимит, а не баг.
- Напоминания привязаны к московскому времени. Если нужна другая зона, меняй `MSK` в `db.py`.
- SQLite подходит для небольшого проекта. Если вырастешь до тысяч пользователей, понадобится Postgres.
- Статусы оплаты в Lava стоит проверять на реальном маленьком платеже до запуска рекламы.
- Если после цикла роликов нет ни одной продажи — проблема в оффере и трафике, а не в коде.

Пользуйся как хочешь: копируй, ломай, переделывай под свою идею.
