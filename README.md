# Хаб-бот · Python

Это ветка `main` — версия на Python (`aiogram 3`). Рядом есть ветка [`rust`](https://github.com/klogore554/hatch-bot/tree/rust): тот же бот на Rust, те же команды и та же механика роста. Ридми в ветках разные: здесь про Python, там про Rust.

Телеграм-бот для привычек: галочка каждый день, серии, групповой челлендж, бесплатная версия и Pro. Форкай, меняй токен и тексты — остальное уже работает.

## Python или Rust

| | `main` (Python) | `rust` (Rust) |
|---|---|---|
| Язык | Python 3.10+ | Rust 1.75+ |
| Запуск | `python bot.py` | `cargo run --release` |
| Данные | SQLite, `habit.db` | JSON, `habit.json` |
| Старт | секунды | почти мгновенно |
| Память | больше | меньше |
| Править логику | легко, синтаксис понятный | нужно знать Rust |
| Выбрать, если | хочешь быстро переделать под себя | важен отклик и расход ресурсов |

Обе ветки работают с Lava и используют один и тот же `CONTENT.md`.

## Зачем так сделано

Одиночная напоминалка быстро надоедает и не приводит новых людей. Поэтому внутри две механики, которые работают без тебя:

- **Рефералка.** Кидаешь ссылку — двое друзей запустили бота, у всех троих +3 дня Pro.
- **Групповой челлендж.** `/challenge` в чате на 7 дней, бот показывает рейтинг. Увидев отстающих, люди сами зовут других.

Плюс обычная польза: привычки, серии, напоминания и оплата без сайта.

## Что умеет

- `/start` с метками `?start=vid1`, `?start=ref123` — видно, откуда пришёл человек и кто пригласил;
- привычки из пресетов и свои: 1 в Free, без лимита в Pro;
- кнопки «✅ Отметить» и «📊 Стрик», напоминание `/remind 09:00` по Москве;
- групповой `/challenge` и рейтинг `/top`;
- кнопка «📄 Документы»: оферта, возврат, политика данных;
- `/subscribe` → email для чека → ссылка на оплату Lava;
- проверка оплаты раз в минуту, автопродление Pro на 30 дней;
- предупреждение за 3 дня до конца Pro;
- `HEALTH_SERVER=1` поднимает `/health`.

Всё основное — кнопками. Команды тоже работают, но искать их пользователю не надо.

## Быстрый старт

Нужен Python 3.10+ и токен бота от `@BotFather`.

```powershell
git clone <твой-форк>.git
cd habit-bot
python -m pip install -r requirements.txt
$env:BOT_TOKEN = "токен_от_botfather"
python bot.py
```

Без ключей Lava бот запустится. `/subscribe` будет ругаться — это нормально, пока оплата не настроена.

Проверка живости: `http://localhost:8000/health` должен вернуть `{"ok":true}`.

## Переменные окружения

`.env` в репозитории нет, всё задаётся на хосте.

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | токен из `@BotFather` |
| `LAVA_SHOP_ID` | UUID магазина в Lava |
| `LAVA_SECRET_KEY` | секретный ключ проекта |
| `LAVA_PRODUCT_ID` | UUID рекуррентного продукта |
| `DB_PATH` | путь к базе, например `/data/habit.db` |
| `PORT` | порт health-сервера |
| `HEALTH_SERVER` | `1` — включить `/health` |
| `LEGAL_NAME`, `LEGAL_INN` | реквизиты продавца в оферте |
| `SUPPORT_EMAIL`, `SUPPORT_TG` | контакты поддержки |

Если `LEGAL_*` и `SUPPORT_*` не задать, документы всё равно откроются — просто без реквизитов. Для реальной модерации их надо заполнить.

## Деплой на Railway

1. New Project → Deploy from GitHub repo, Branch: `main`.
2. Settings → Variables: добавь переменные из таблицы.
3. Settings → Volumes: смонтируй Volume на `/data`.
4. Start Command: `python bot.py` — в `Procfile` уже так.
5. Проверь `GET /health`.

Volume нужен, чтобы база не исчезала при redeploy. Без него привычки и серии обнулятся. Хостинг с постоянным адресом обязателен: Lava при модерации не любит временные домены.

## Оплата и деньги

Подключена Lava. Рекуррентный продукт создаётся в личном кабинете, цена и период задаются там же. Webhook не используется: бот сам опрашивает `/business/recurrent/subscription/status` раз в минуту и продлевает Pro, если статус оплачен. Точные значения статусов стоит сверить с документацией Lava — в `payments/lava.py` есть функция `looks_paid()`, её легко подправить.

Другой платёжный сервис — меняй только папку `payments/`. Логика бота от этого не зависит.

Вывод денег делается в личном кабинете платёжного сервиса. Отдельного скрипта для этого нет и не нужно.

Что видно покупателю: название магазина, продукт, цена и чек. Реквизиты, документы и телефон остаются в личном кабинете провайдера — в репозитории их нет. Для поддержки лучше держать отдельную почту и Telegram-аккаунт и не терять к ним доступ.

## Как форкнуть под себя

1. Замени метки `vid1…vid7` в `CONTENT.md` на свои.
2. Поменяй `PRESETS` в `bot.py` — набор привычек под свою аудиторию.
3. Поправь тексты в `legal.py`. Реальные реквизиты не вписывай в файл — они приходят из переменных окружения.
4. Перепиши ролики в `CONTENT.md`, там готовый каркас.
5. Создай свой рекуррентный продукт в Lava и задай три переменные `LAVA_*`.
6. Другую цену поменяй и в Lava, и в текстах бота, и в контенте.

Структура: `bot.py` — хендлеры и кнопки, `db.py` — SQLite, `legal.py` — документы, `payments/lava.py` — платёжный клиент, `CONTENT.md` — ролики и deep-link.

После слива веток в `main` здесь также лежат файлы Rust-порта (`Cargo.toml`, `src/`). Это не ошибка: чтобы собрать Rust-версию, возьми ветку `rust` — там всё подготовлено именно под неё.

## Ограничения

- Одна привычка в Free — лимит, а не баг.
- Напоминания привязаны к московскому времени. Другая зона — правка `MSK` в `db.py`.
- SQLite подходит для небольшого проекта. На тысячи пользователей понадобится Postgres.
- Статусы оплаты Lava стоит проверить маленьким реальным платежом до запуска рекламы.
- Если после цикла роликов нет ни одной продажи — проблема в оффере и трафике, а не в коде.

Пользуйся как хочешь: копируй, ломай, переделывай под свою идею.
