# Хаб-бот

Телеграм-бот с привычками, стриками, групповым челленджем, реферальной механикой и подпиской.

**Механика роста — сарафанное радио, а не одиночные напоминания:**

- `/referral` — два приглашённых пользователя дают обоим +3 дня Pro;
- `/challenge` в группе — общий рейтинг на 7 дней, участники сами приглашают других;
- челлендж может запустить любой участник.

## Что уже есть

- `/start` с deep-link: `?start=vid1` / `?start=ref123` — учитывается источник запуска и пригласивший;
- привычки из пресетов и свои, лимит 1 в Free и без лимита в Pro;
- ✅-отметки, стрики, `/remind 09:00` (МСК);
- групповой челлендж, кнопка «Я сделал», рейтинг `/top`;
- `/subscribe` → ввод email для чека → платёжная ссылка;
- статус подписки проверяется раз в минуту, Pro продлевается автоматически;
- предупреждение за 3 дня до окончания Pro;
- `HEALTH_SERVER=1` поднимает `/health` для проверки деплоя.

## Настройка

### Модерация платёжного сервиса

Все данные и документы для модерации передаются напрямую в личный кабинет платёжного провайдера.  
В этом репозитории их нет и они не попадают в код.

### Переменные окружения

- `BOT_TOKEN` — токен, выданный `@BotFather`;
- `LAVA_SHOP_ID` — UUID магазина;
- `LAVA_SECRET_KEY` — секретный ключ проекта;
- `LAVA_PRODUCT_ID` — UUID рекуррентного продукта;
- `DB_PATH` — путь к базе, на Railway лучше `/data/habit.db`;
- `PORT` — задаётся хостингом;
- `HEALTH_SERVER=1`;
- `LEGAL_NAME`, `LEGAL_INN` — данные продавца для оферты;
- `SUPPORT_EMAIL`, `SUPPORT_TG` — контакты поддержки для документов.

Документы доступны в боте кнопкой **«📄 Документы»**: оферта, возврат и политика данных. Тексты лежат в `legal.py`, персональные данные подставляются из переменных окружения и в репозитории не хранятся.

Файл `.env` не используется — переменные задаются на хосте/в панели хостинга.

## Локальный запуск

```powershell
cd D:\project\habit-bot
python -m pip install -r requirements.txt
$env:BOT_TOKEN="токен_от_botfather"
python bot.py
```

Без ключей платёжного сервиса бот запускается, но `/subscribe` сообщит об ошибке — это ожидаемо.

## Railway

1. Новый проект → Deploy from GitHub repo (папка `habit-bot`).
2. Settings → Variables — добавить переменные выше.
3. Settings → Volumes → смонтировать Volume на `/data`.
4. Start Command: `python bot.py`.
5. Проверка: `GET /health` возвращает `{"ok":true}`.

Платный хостинг с фиксированным адресом подходит для модерации платёжного сервиса.

## Платёжный слой

Сейчас модуль рассчитан на Lava. При смене провайдера меняется только каталог `payments/`, логика бота не трогается.

Webhook не обязателен: бот сам опрашивает статус подписки раз в минуту.  
Точные значения статусов стоит сверить с документацией выбранного провайдера — в коде есть эвристика `lava.looks_paid()`.

## Вывод на TRC-20

У Lava есть вывод в USDT сети TRC-20 — отдельный провайдер для этого не нужен. Модуль `payments/lava_payoff.py` оборачивает четыре метода:

| Метод | Что делает |
|---|---|
| `POST /business/payoff/check-wallet` | проверяет кошелёк до вывода |
| `POST /business/payoff/get-tariffs` | комиссии и лимиты |
| `POST /business/payoff/create` | создаёт заявку с `service: "trc20_payoff"` |
| `POST /business/payoff/info` | статус: `created`, `pending`, `success`, `rejected` |

Дополнительные переменные окружения:

- `LAVA_PROFILE_ID` — UUID профиля из личного кабинета;
- `LAVA_WALLET_TO` — адрес кошелька TRON (начинается с `T`, 34 символа).

Вывод делается вручную отдельным скриптом, бот его не вызывает:

```powershell
python payoff.py check
python payoff.py tariffs
python payoff.py create 1000
python payoff.py info payoff-xxxxxxxxxxxx
```

`create` запрашивает подтверждение. Сумма и валюта вывода, а также значение `subtract` стоит сверить с тарифами и поддержкой до первого реального вывода.

## Приватность

Что видно покупателю:

- название магазина/продукта и цену на странице оплаты;
- в чеке — данные продавца, предусмотренные законодательством;
- в выписке — выплату от платёжного сервиса, а не реквизиты продавца.

Что остаётся только в личном кабинете платёжного сервиса: документы, ИНН, адрес, телефон. В репозитории и в коде этих данных нет.

Контакты для поддержки можно держать отдельными: другой Telegram-аккаунт и отдельная почта. Это нормальная практика. Но:

- почта должна быть долгоживущей — включи двухфакторную защиту и сохрани коды восстановления;
- телефон для подтверждения тоже лучше завести отдельный и надолго — виртуальные номера часто переиспользуют, и тогда теряется доступ к аккаунту;
- юридические данные (ФИО, ИНН) должны быть настоящими — подмена данных создаёт проблемы с выплатами и налогами;
- общение с поддержкой — только через контакты с официального сайта платёжного сервиса; в Telegram много поддельных «поддержек».

## Контент

`CONTENT.md` — 7 нейтральных скриптов и три кнопки для Taplink.

План:

1. Записать все 7 роликов за один день.
2. Залить их через планировщик платформы.
3. Неделю не возвращаться к контенту.
4. Смотреть по меткам `vid1…vid7`, какой ролик дал запуски.

Даже небольшой аудитории достаточно, чтобы проверить воронку. Стабильный результат требует регулярного трафика.

## Важно

- Если после цикла роликов нет ни одной продажи — меняем оффер или идею, а не дописываем код.
- Способы вывода средств зависят от условий провайдера — уточняй их в личном кабинете.
- Чеки и документы храни согласно требованиям провайдера и законодательства.
